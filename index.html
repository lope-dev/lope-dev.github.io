About Me

Engineer by trade,
problem-solver by habit

I came into tech through an unusual path: a degree in Environmental Science, then a deliberate pivot into cloud infrastructure when I realized the hardest problems in the world run on data. That outsider perspective stuck. I still care more about what the system does for real people than whether it looks impressive in a diagram.

At Foundation Medicine, the AI work goes deep. I built the retrieval layer for a production RAG platform on Amazon Bedrock and OpenSearch, handling document chunking, hybrid keyword-semantic search, and embedding strategies tuned for clinical genomic text. The platform now serves 50,000+ documents at under three seconds per query, with relevance more higher than the baseline system it replaced.

On the agentic side, I designed a multi-agent LLM platform in LangGraph and AWS Bedrock Agents with specialized agents covering clinical, and research workflows. Getting state management, retry logic, and safe fallback paths right across agent boundaries was the interesting engineering challenge. The result was about a 60% reduction in analyst data synthesis time once teams started running production workflows through it.

I also built MCP-compliant tool servers inside our GitHub and Jenkins environments, treating tool surface area as a product: proper input validation, error handling, and documentation so agents could call production tools reliably without unexpected failures cascading through a workflow. And I wired Salesforce CRM into our AI summarization layer via REST and webhooks, which brought over 200 internal users onto the integration within the first quarter.

The infrastructure side runs in parallel: three-tier application deployments via Terraform and CloudFormation, Dockerized services through ECR and ECS, CI/CD through GitHub Actions and Jenkins, and cost visibility through AWS myApplication so teams know exactly what their workloads cost.
